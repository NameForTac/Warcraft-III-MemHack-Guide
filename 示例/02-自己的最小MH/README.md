# 自己的最小 MH：1.27a 特效透明度案例

本案例已从架构草图补齐为自包含 JASS 源码，入口位于 [mini-mh](mini-mh/README.md)。地图接入、完整绝对路径 `#include` 清单、调用示例和诊断输出均以该说明为准。

## 实现链路

```text
MiniMH_Init
  -> 特殊入口启动 JASS 内存桥
  -> 检查 1.27a 版本特征与 Game.dll 头
  -> 检查句柄表
  -> 分配机器码缓冲区并恢复临时原生入口

MiniMH_SetEffectAlpha(effect, alpha)
  -> 检查参数
  -> 特效句柄转换为对象地址
  -> 读取精灵指针
  -> 写入并回读 36 字节调用机器码
  -> 临时重定向原生入口，执行内部透明度函数
  -> 恢复原始入口并回读确认
```

## 已验证与待验证

用户的本机 1.27a 游戏测试已确认进图、初始化、版本检查、机器码写入回读、内部调用返回和原生入口恢复。透明度字段回读与可见效果对比仍待验证；源码返回 `true` 表示调用流程通过，不代表视觉效果已被独立确认。

## 阅读顺序

按 `core.j`、`version_127a.j`、`typecast.j`、`memory.j`、`handle_table.j`、`calls.j`、`effect_alpha.j`、`entry.j` 阅读。地址集中在版本文件，地图作者通过公开函数调用，无需直接操作内部地址。

虚拟机转换、特殊启动方式和调用链参考 [UnryzeC/MemHackAPI](https://github.com/UnryzeC/MemHackAPI)。本目录自行提供所需实现，不需要 include 上游地图源码。保留编译指令、变量名称和函数顺序，详细布局约束见 [项目接入说明](mini-mh/README.md#必须保留的布局)。

扩展其他 API 时，先确认该功能的对象路径、版本偏移和调用约定，再复用内存桥与句柄转换。不能从本次透明度调用验证推导出其他对象或游戏版本也适用。
